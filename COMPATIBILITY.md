# Compatibility Matrix

This document outlines the compatibility between different versions of the LLM4S template, the LLM4S framework, and Scala versions.

## Version Compatibility

| Template Version | LLM4S Versions | Scala Versions | Java Version | Status |
|-----------------|----------------|----------------|--------------|---------|
| 1.2.x           | 0.5.x (default `0.5.1`) | 3.7.1 | 21 | Current |
| 1.1.x           | 0.4.x (default `0.4.0`) | 3.7.1 | 21 | Superseded |
| 1.0.x           | 0.1.0 - 0.1.x  | 2.13.16, 3.7.1 | 21 | Broken — see below |

The canonical support matrix for the library itself lives in the main repository at
[`docs/reference/v1-scope.md`](https://github.com/llm4s/llm4s/blob/main/docs/reference/v1-scope.md).
This document only records what the template generates.

## Detailed Compatibility

### Template v1.2.x (current)

**LLM4S artifacts:** `llm4s-core`, `llm4s-ollama` and `llm4s-openai` (plus `llm4s-testkit` in
`Test`), all at one `llm4sVersion`.

LLM4S 0.5.0 split the old single `llm4s-core` artifact: core no longer contains any provider, so a
project that depends on `llm4s-core` alone fails at the first call with "Provider '...' is not
registered". The template therefore adds two provider modules - `llm4s-ollama` (the default
`ollama-local` section, which needs no API key) and `llm4s-openai` (the `openai-main` section,
which reads `OPENAI_API_KEY`). Other providers are one dependency each (`llm4s-anthropic`,
`llm4s-gemini`, `llm4s-openai-compatible`, ...). The published modules also no longer bring a
logging backend, so the template declares `logback-classic` itself.

The template lists explicit modules on one version val rather than importing `llm4s-bom`: sbt
does not apply a Maven BOM's `dependencyManagement`, and every llm4s module is released at the
same version, so one val gives the same alignment.

**Supported LLM4S Versions:**
- 0.5.1 ✅ (default)
- 0.5.0 ✅ (`llm4s-testkit` is published from 0.5.0)

**Supported Scala Versions:**
- 3.7.1 ✅ (default, and the version llm4s 0.5.x is built with)

**Supported Java Versions:**
- Java 21 ✅ (required)

Upgrading a project generated by template 1.1.x (llm4s 0.4.0): follow the library's
[0.4.1 to 0.5.0 upgrade guide](https://github.com/llm4s/llm4s/blob/main/docs/migrations/0-4-1-to-0-5-0.md).
For this template's generated code that means: add `llm4s-ollama` and/or `llm4s-openai` next to
`llm4s-core`, add `logback-classic`, and drop explicit `apiKey = ${?OPENAI_API_KEY}` lines if you
like (the provider module now binds the variable for you).

### Template v1.1.x

**LLM4S artifact:** `"org.llm4s" %% "llm4s-core"`.

The artifact coordinates have changed twice, so the name matters as much as the version:

| Coordinate | Versions | Status |
|-----------|----------|--------|
| `org.llm4s:llm4s` (aggregate) | up to 0.2.9 | No longer published |
| `org.llm4s:core` | up to 0.3.4 | Frozen at 0.3.4 |
| `org.llm4s:llm4s-core` | 0.4.0 onward | Current (0.5.0+: no providers; add `llm4s-<provider>` modules) |

`org.llm4s:llm4s` — the aggregate artifact that template v1.0.x depended on — is **no longer
published**: the root project in the library build sets `publish / skip := true`, and the last
published `llm4s_3` / `llm4s_2.13` was 0.2.9. Publishing continued under `org.llm4s:core` through
0.3.4, and the 0.4.0 release renamed the published modules to the `llm4s-*` prefix, making
`org.llm4s:llm4s-core` the current coordinate. 0.4.0 was a rename-only release — no API changes.

Bumping the version alone does not fix a project generated by an older template; the artifact name
has to change too.

**Supported LLM4S Versions:**
- 0.4.0 ✅ (default in template 1.1.x)

**Supported Scala Versions:**
- 3.7.1 ✅ (default, and the only supported version)

**Supported Java Versions:**
- Java 21 ✅ (required)

### Scala 2.13

Scala 2.13 is **not supported** by this template going forward.

- `core_2.13` was last published at **0.2.9** (2026-01-11); the Scala 3 line has continued
  (`core_3` through 0.3.4, then `llm4s-core_3` from 0.4.0). There is no `llm4s-core_2.13`.
- LLM4S 1.0 targets **Scala 3 only (3.7.1)**. Scala 2.13 support is deferred to post-1.0 and, if
  it happens, would target a subset of the module tree.
- Tracking issue: [llm4s#874](https://github.com/llm4s/llm4s/issues/874).

If you need Scala 2.13, the last usable release is `"org.llm4s" %% "core" % "0.2.9"`, which is not
receiving updates. Generating with

```bash
sbt new llm4s/llm4s.g8 --scala_version=2.13.16 --llm4s_version=0.2.9
```

is **not sufficient on its own**: the generated `build.sbt` asks for `llm4s-core`, which has no
0.2.9 release, so the artifact name has to be changed back to `core` by hand. The 0.2.9 API also
differs from 0.3.x/0.4.x, so the generated sources will need adjusting.

### Known bad versions

A version numbered `2.1.593` appears on Maven Central for `core_3` and `core_2.13`. It is an
accidental mis-publish (a typo) that cannot be retracted — do not use it.

**Features:**
- Full LLM4S API support
- Example applications
- Test setup with Munit
- GitHub Actions CI/CD
- Scalafmt configuration
- Environment configuration

## Version Selection Guide

### For New Projects

Use the latest template version with the latest stable LLM4S version:

```bash
sbt new llm4s/llm4s.g8
```

This will use:
- Latest template version
- LLM4S 0.5.1 (current default)
- Scala 3.7.1 (current default)

### For a specific LLM4S version

```bash
sbt new llm4s/llm4s.g8 --llm4s_version=0.5.1
```

Any `0.5.x` release should work. A `0.4.x` version will not: the provider modules and `llm4s-testkit` do not exist before 0.5.0, so use template 1.1.x for 0.4.x. Note that versions **at or below 0.3.4 will not
resolve with this template**, because they were published under the older `org.llm4s:core`
coordinate — to use one you must also edit the artifact name in the generated `build.sbt`.

## Migration Guide

### From Embedded Template to Standalone

If you were previously using the template from the main LLM4S repository:

1. The new template location is `llm4s/llm4s.g8`
2. All parameters remain the same
3. The generated project structure is identical

### Upgrading Template Versions

To upgrade to a newer template version for an existing project:

1. Note your current LLM4S and Scala versions
2. Generate a new project with the latest template
3. Compare and merge changes as needed

## Deprecation Policy

- Template versions are supported for at least 6 months after release
- Deprecation notices will be added to this document 3 months before end of support
- Security fixes will be backported to supported versions

## Testing Matrix

The combination in the compatibility matrix is tested in CI (template generation plus a real
`sbt compile test` inside the generated project):

- ✅ Template generation succeeds
- ✅ Generated project compiles
- ✅ Generated project tests pass
- ✅ Scalafmt validation passes

## Known Issues

- Template v1.0.x generates projects that cannot resolve their dependency: it points at
  `"org.llm4s" %% "llm4s" % "0.1.9"`, an artifact that is no longer published. Regenerate with the
  current template.
